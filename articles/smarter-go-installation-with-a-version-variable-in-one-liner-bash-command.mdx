<p>When you’re managing multiple systems or setting up developer environments frequently, even a simple Go installation script can benefit from <strong>a small optimization</strong>—especially when it involves <strong>repetition of version numbers</strong>.</p><p>Let’s break down an enhanced version of a common one-liner used to install Go on Linux, and why <strong>using a variable</strong> is the better way.</p><hr><h2 id="%F0%9F%94%A7-the-original-command">🔧 The Original Command</h2><p>You might often see or use this:</p><pre><code class="language-bash">wget https://go.dev/dl/go1.24.4.linux-amd64.tar.gz &amp;&amp; sudo rm -rf /usr/local/go &amp;&amp; sudo tar -C /usr/local -xzf go1.24.4.linux-amd64.tar.gz &amp;&amp; go version &amp;&amp; rm go1.24.4.linux-amd64.tar.gz
</code></pre><p>It works just fine—but the <strong>version number is repeated three times</strong>, which means if you want to install a different version next time, you need to change it <strong>in three places</strong>.</p><p>This is error-prone and not elegant.</p><hr><h2 id="%E2%9C%85-the-improved-version-use-a-version-variable">✅ The Improved Version: Use a Version Variable</h2><p>Let’s introduce a version variable to clean this up:</p><pre><code class="language-bash">VER=1.24.4 &amp;&amp; wget https://go.dev/dl/go$VER.linux-amd64.tar.gz &amp;&amp; sudo rm -rf /usr/local/go &amp;&amp; sudo tar -C /usr/local -xzf go$VER.linux-amd64.tar.gz &amp;&amp; /usr/local/go/bin/go version &amp;&amp; rm go$VER.linux-amd64.tar.gz
</code></pre><h3 id="%F0%9F%94%8D-what-changed-and-why-it%E2%80%99s-better">🔍 What Changed and Why It’s Better:</h3><ul><li><strong><code>VER=1.24.4</code></strong> at the start makes it easy to <strong>change the version once</strong>.</li><li>All <code>go$VER.linux-amd64.tar.gz</code> references become dynamic.</li><li>Using <code><strong>/usr/local/go/bin/go version</strong></code> ensures we’re testing the newly installed Go version, even if the current shell hasn’t reloaded <code>$PATH</code>.</li></ul><hr><h2 id="%F0%9F%A7%A0-why-use-an-absolute-path-for-go-version">🧠 Why Use an Absolute Path for <code>go version</code>?</h2><p>When Go is installed to <code>/usr/local/go</code>, it’s usually <strong>not in your PATH until a new shell is opened</strong> or your profile (<code>~/.bashrc</code>, <code>~/.zshrc</code>, etc.) sources it.</p><p>By using:</p><pre><code class="language-bash">/usr/local/go/bin/go version
</code></pre><p>…you ensure that the version check points <strong>directly to the new binary</strong>, not an older version in your PATH.</p><hr><h2 id="%E2%9A%A0%EF%B8%8F-other-considerations">⚠️ Other Considerations</h2><p>Here are a few <strong>additional things you might want to think about</strong>:</p><h3 id="1-clean-path-configuration">1. <strong>Clean PATH Configuration</strong></h3><p>Make sure your shell config includes:</p><pre><code class="language-bash">export PATH=$PATH:/usr/local/go/bin
</code></pre><p>Otherwise, the <code>go</code> command won’t be available unless you call it by full path.</p><hr><h3 id="2-use-a-safer-tmp-directory">2. <strong>Use a Safer TMP Directory</strong></h3><p>To avoid clutter or accidental file overwrites, consider downloading into a temporary directory:</p><pre><code class="language-bash">VER=1.24.4 &amp;&amp; TMP_DIR=$(mktemp -d) &amp;&amp; cd $TMP_DIR &amp;&amp; \
wget https://go.dev/dl/go$VER.linux-amd64.tar.gz &amp;&amp; \
sudo rm -rf /usr/local/go &amp;&amp; \
sudo tar -C /usr/local -xzf go$VER.linux-amd64.tar.gz &amp;&amp; \
/usr/local/go/bin/go version &amp;&amp; \
cd ~ &amp;&amp; rm -rf $TMP_DIR
</code></pre><p>This ensures <strong>no leftover tarballs</strong> and isolates the process nicely.</p><hr><h3 id="3-use-sha256sum-for-integrity-check-optional-but-recommended">3. <strong>Use <code>sha256sum</code> for Integrity Check (Optional but Recommended)</strong></h3><p>Each Go release provides a SHA256 checksum file. If you’re concerned about integrity:</p><pre><code class="language-bash">wget https://go.dev/dl/go$VER.linux-amd64.tar.gz.sha256
sha256sum -c go$VER.linux-amd64.tar.gz.sha256
</code></pre><p>This adds <strong>extra security and integrity validation</strong>, especially when automating.</p><hr><h2 id="%F0%9F%8E%AF-finally">🎯 Finally</h2><p>Using a variable like <code>VER=1.24.4</code> in your one-liner Go install script:</p><ul><li><strong>Reduces repetition</strong></li><li><strong>Prevents errors</strong></li><li><strong>Makes updates easier</strong></li><li><strong>Improves maintainability</strong></li></ul><p>If you're setting up Go across multiple environments or provisioning with scripts, <strong>this small change makes a big difference</strong>.</p><p>Keep your tools clean, your scripts DRY, and your installations versioned properly. 🧼</p><h3 id="support-us">Support Us</h3>
