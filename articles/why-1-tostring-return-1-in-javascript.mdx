<p>The expression <code>1..toString()</code> returns the string <code>"1"</code>. Here's how it works:</p><ol><li><strong><code>1.</code> (the first <code>.</code> after <code>1</code>)</strong>: This is treated as part of the <a href="__GHOST_URL__/what-is-numeric-literal-in-javascript/" rel="noreferrer">numeric literal</a>. JavaScript requires the second <code>.</code> to distinguish between a floating-point number and a method call. If you just wrote <code>1.toString()</code>, JavaScript would think you're trying to access a property on <code>1</code> (a number) but wouldn't know where the number ends and where the property access begins. So, you add an extra <code>.</code> to make it clear.</li><li><code><strong>toString()</strong></code>: This is a method of the <code>Number</code> object in JavaScript. It converts the number <code>1</code> to its string representation.</li></ol><p>Thus, the code <code>1..toString()</code> calls the <code>toString()</code> method on the number <code>1</code> and returns the string <code>"1"</code>.</p><p>Based on that information, we can say <code>1.toString()</code> will not the same like <code>1..toString()</code> .</p><h3 id="why">Why?</h3><ul><li><code>1.toString()</code> will result in a <strong>syntax error</strong> because JavaScript interprets the first dot after the <code>1</code> as part of a decimal number, expecting something like <code>1.0</code>. It doesn’t know that you intend to call the <code>toString()</code> method.</li><li><code>1..toString()</code> works because the first <code>.</code> after <code>1</code> is interpreted as the decimal point (so it's treated as <code>1.0</code>), and the second <code>.</code> is used to access the method <code>toString()</code>.</li></ul><h3 id="key-difference">Key difference:</h3><ul><li><code><strong>1.toString()</strong></code>: This fails because JavaScript expects the dot to be part of the number literal, so it doesn't recognize <code>toString()</code> as a method call.</li><li><code><strong>1..toString()</strong></code>: The first dot forms the complete numeric literal (<code>1.</code> or <code>1.0</code>), and the second dot accesses the method <code>toString()</code>.</li></ul><h3 id="example">Example:</h3><ul><li><code>1.toString()</code> → <strong>Syntax Error</strong>: The parser doesn’t know where the number ends and the method call starts.</li><li><code>1..toString()</code> → <code>"1"</code>: The first dot finalizes the numeric literal, and the second dot allows the method call.</li></ul><h3 id="alternative-ways-to-call-tostring-on-a-number">Alternative ways to call <code>toString()</code> on a number:</h3><ol><li><code>1..toString()</code></li><li><code>(1).toString()</code> — parentheses help clarify the numeric literal.</li><li><code>1.0.toString()</code></li></ol><p>So while both aim to call <code>toString()</code> on the number <code>1</code>, only <code>1..toString()</code> or <code>(1).toString()</code> works in this case.</p><p>Hope it helps.</p><h3 id="support-us">Support Us</h3>
