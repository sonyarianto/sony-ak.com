<p>If you're running a <strong>self-hosted Ghost blog with Docker</strong> and you've made changes to your theme—only to find that <strong>nothing has changed on your site</strong>—you're not alone. This is a common pitfall when working with Ghost and Dockerized environments. Let's break down what might be going wrong and how to fix it properly.</p><hr><h2 id="1-ghost-doesn%E2%80%99t-auto-reload-themes"><strong>1. Ghost Doesn’t Auto-Reload Themes</strong></h2><p>First things first: <strong>Ghost doesn’t watch your theme files for changes</strong>.</p><p>If you edit theme files (like <code>default.hbs</code>, <code>post.hbs</code>, or CSS/JS assets), Ghost <strong>won’t apply those changes until you restart the container</strong>.</p><h3 id="%E2%9C%85-fix-restart-the-ghost-container">✅ Fix: Restart the Ghost container</h3><p>If you’re using Docker Compose and your service is called <code>service-ghost</code>, you just need to run:</p><pre><code class="language-bash">docker compose restart service-ghost
</code></pre><p>Or if you’re using the older <code>docker-compose</code> command:</p><pre><code class="language-bash">docker-compose restart service-ghost
</code></pre><p>This tells Docker to stop and start only that one service—no need to take your whole stack down.</p><hr><h2 id="2-are-you-editing-the-right-theme"><strong>2. Are You Editing the Right Theme?</strong></h2><p>It may sound obvious, but Ghost can store multiple themes—and you might be editing the wrong one.</p><h3 id="%E2%9C%85-fix-check-the-active-theme">✅ Fix: Check the active theme</h3><p>Go to your Ghost admin panel:</p><pre><code>http://yourdomain.com/ghost
</code></pre><p>Navigate to:</p><pre><code>Settings → Design → Change theme
</code></pre><p>Make sure the theme you’re editing (e.g., <code>headline</code>) is the <strong>active one</strong>.</p><hr><h2 id="3-are-you-editing-the-theme-in-the-right-location"><strong>3. Are You Editing the Theme in the Right Location?</strong></h2><p>When using Docker, Ghost stores themes <strong>inside the container</strong> at:</p><pre><code>/var/lib/ghost/content/themes/
</code></pre><p>However, most setups <strong>mount this directory to your host machine</strong> using volumes. If you're editing theme files inside the wrong place (like your local system, but it’s not mounted), Ghost won’t see the changes.</p><h3 id="%E2%9C%85-fix-verify-your-volume-mount">✅ Fix: Verify your volume mount</h3><p>In your <code>docker-compose.yml</code>, make sure you have something like this:</p><pre><code class="language-yaml">volumes:
  - ./ghost-content:/var/lib/ghost/content
</code></pre><p>This means your themes are located on your host at:</p><pre><code>./ghost-content/themes/headline/
</code></pre><p>Edit files here—not inside the container unless you know what you’re doing.</p><p>You can confirm where it’s actually mounted with:</p><pre><code class="language-bash">docker inspect service-ghost
</code></pre><p>Look under the <code>Mounts</code> section.</p><hr><h2 id="4-clear-browser-cache-and-force-reload"><strong>4. Clear Browser Cache and Force Reload</strong></h2><p>Modern browsers are aggressive about caching. Even if Ghost is serving your updated files, your browser might still be showing you the old version.</p><h3 id="%E2%9C%85-fix-do-a-hard-refresh">✅ Fix: Do a hard refresh</h3><ul><li><strong>Windows/Linux</strong>: <code>Ctrl + Shift + R</code></li><li><strong>macOS</strong>: <code>Cmd + Shift + R</code></li></ul><p>Also try incognito mode or another browser to rule out caching issues.</p><hr><h2 id="5-check-for-errors-in-your-theme-code"><strong>5. Check for Errors in Your Theme Code</strong></h2><p>If your <code>.hbs</code> or <code>.css</code> changes have syntax errors, Ghost may fail silently or fall back to default rendering.</p><h3 id="%E2%9C%85-fix-review-ghost-logs">✅ Fix: Review Ghost logs</h3><p>Run:</p><pre><code class="language-bash">docker logs service-ghost
</code></pre><p>Look for anything suspicious like:</p><pre><code>Failed to compile template
Unhandled exception
</code></pre><p>Fix the code, then restart Ghost again.</p><hr><h2 id="6-re-upload-the-theme-if-all-else-fails"><strong>6. Re-upload the Theme (If All Else Fails)</strong></h2><p>Sometimes changes get messy. As a last resort, you can <strong>zip your modified theme and upload it through the Ghost admin UI</strong>.</p><p>Go to:</p><pre><code>Settings → Design → Change theme → Upload a theme
</code></pre><p>This forces Ghost to reload and register the theme anew.</p><hr><h2 id="%E2%9C%A8-bonus-tips">✨ Bonus Tips</h2><ul><li><strong>Version control your themes</strong> (Git): This helps keep track of what changed and makes it easy to roll back.</li><li><strong>Use local development</strong>: Test your theme changes locally before deploying them via Docker.</li><li><strong>Avoid editing themes inside the container</strong>: Any change made inside the container without a mounted volume will be <strong>lost if the container is rebuilt</strong>.</li><li><strong>Restarting all services</strong>: If you’re unsure which service is to blame, a full restart helps:</li></ul><pre><code class="language-bash">docker compose down
docker compose up -d
</code></pre><hr><h2 id="%F0%9F%A7%A0-finally">🧠 Finally</h2><p>Docker is great for isolating environments, but it introduces some complexity when dealing with file changes—especially with CMSs like Ghost. Always make sure:</p><ul><li>You edit in the right directory</li><li>You restart the container after edits</li><li>You check that the theme is active</li><li>You clear cache and watch the logs</li></ul><p>With these steps, your theme changes should now appear as expected. If not, it's almost always related to one of the above issues.</p><h3 id="support-us">Support Us</h3>
