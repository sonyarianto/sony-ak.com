<p>When working with identifiers like <strong><code>r1</code>, <code>r20</code>, <code>r100</code></strong>, or <strong><code>smk1</code>, <code>smk50</code>, <code>smk200</code></strong>, it is common to expect them to sort in a natural, human-friendly order. Unfortunately, default MySQL sorting follows <em>pure lexicographical rules</em>, which often leads to unintuitive results such as:</p><pre><code>smk1
smk100
smk20
</code></pre><p>This article explains <em>why</em> this happens, <em>how</em> to fix it properly, and what additional considerations you may need to handle depending on your data structure.</p><hr><h2 id="why-default-mysql-sort-fails-for-mixed-slugs"><strong>Why Default MySQL Sort Fails for Mixed Slugs</strong></h2><p>MySQL compares strings <strong>character by character</strong>. Therefore:</p><ul><li><code>'s'</code> = <code>'s'</code></li><li><code>'m'</code> = <code>'m'</code></li><li><code>'k'</code> = <code>'k'</code></li><li><code>'1'</code> &lt; <code>'2'</code> &lt; <code>'9'</code>, but <code>'1'</code> is also &lt; <code>'20'</code> because <code>'1'</code> is compared to <code>'2'</code>.</li></ul><p>So MySQL thinks:</p><ul><li><strong><code>smk100</code> &lt; <code>smk20</code></strong><br>because <code>'1'</code> (from <code>100</code>) is less than <code>'2'</code> (from <code>20</code>).</li></ul><p>This is valid lexicographically, but wrong for natural numeric expectations.</p><hr><h2 id="correct-approach-extract-and-sort-by-the-numeric-part"><strong>Correct Approach: Extract and Sort by the Numeric Part</strong></h2><p>Since your slugs start with a <strong>prefix</strong> (<code>smk</code>, <code>r</code>, etc.) followed by a number, the solution is simple:</p><h3 id="1-remove-the-prefix"><strong>1. Remove the prefix</strong></h3><p>Use <code>SUBSTRING()</code> to skip the first characters.</p><h3 id="2-convert-the-remainder-to-a-number"><strong>2. Convert the remainder to a number</strong></h3><p>Use <code>CAST(... AS UNSIGNED)</code> for numeric sorting.</p><h3 id="3-order-using-the-numeric-value"><strong>3. Order using the numeric value</strong></h3><hr><h2 id="sorting-slugs-starting-with-smk"><strong>Sorting Slugs Starting with <code>smk</code></strong></h2><p>If all slugs start with <code>'smk'</code> (3 characters):</p><pre><code class="language-sql">SELECT *
FROM `pixie_resources`
WHERE `slug` LIKE 'smk%'
ORDER BY CAST(SUBSTRING(`slug`, 4) AS UNSIGNED);
</code></pre><h3 id="how-it-works">How it works:</h3><ul><li><code>SUBSTRING(slug, 4)</code> → <code>"smk123"</code> becomes <code>"123"</code></li><li><code>CAST(... AS UNSIGNED)</code> ensures <strong>numeric</strong> ordering</li><li>MySQL sorts naturally: <code>smk1</code>, <code>smk2</code>, <code>smk10</code>, <code>smk100</code></li></ul><hr><h2 id="sorting-slugs-with-other-prefixes-general-pattern"><strong>Sorting Slugs with Other Prefixes (General Pattern)</strong></h2><p>If your prefix length varies but you know the prefix itself, adjust accordingly:</p><h3 id="prefix-r">Prefix: <code>r</code></h3><pre><code class="language-sql">ORDER BY CAST(SUBSTRING(slug, 2) AS UNSIGNED)
</code></pre><h3 id="prefix-abc">Prefix: <code>abc</code></h3><pre><code class="language-sql">ORDER BY CAST(SUBSTRING(slug, 4) AS UNSIGNED)
</code></pre><h3 id="prefix-length-unknown-but-alphabetic">Prefix length unknown but alphabetic?</h3><p>Extract numbers using regex-like logic (MySQL 8+):</p><pre><code class="language-sql">ORDER BY REGEXP_SUBSTR(slug, '[0-9]+') + 0;
</code></pre><hr><h2 id="handling-edge-cases-you-may-encounter"><strong>Handling Edge Cases You May Encounter</strong></h2><h3 id="1-slugs-without-numbers"><strong>1. Slugs without numbers</strong></h3><p>Example: <code>smk</code>, <code>smkA</code></p><p>These need a fallback:</p><pre><code class="language-sql">ORDER BY 
  CAST(REGEXP_SUBSTR(slug, '[0-9]+') AS UNSIGNED),
  slug;
</code></pre><p>Slugs with no numbers will sort at the top (numeric value = NULL).</p><h3 id="2-slugs-with-alphanumeric-suffixes"><strong>2. Slugs with alphanumeric suffixes</strong></h3><p>Example: <code>smk10a</code>, <code>smk10b</code></p><p>Use numeric-first, then full slug:</p><pre><code class="language-sql">ORDER BY 
  CAST(SUBSTRING(slug, 4) AS UNSIGNED),
  slug;
</code></pre><h3 id="3-slugs-with-dashes-or-separators"><strong>3. Slugs with dashes or separators</strong></h3><p>Example: <code>smk10-item</code>, <code>smk10-extra</code></p><p>Extract only the numeric part:</p><pre><code class="language-sql">ORDER BY 
  CAST(SUBSTRING_INDEX(SUBSTRING(slug, 4), '-', 1) AS UNSIGNED),
  slug;
</code></pre><h3 id="4-case-sensitivity"><strong>4. Case sensitivity</strong></h3><p>If prefixes may contain mixed case (<code>SMK10</code>, <code>smk10</code>):</p><pre><code class="language-sql">ORDER BY 
  CAST(SUBSTRING(LOWER(slug), 4) AS UNSIGNED),
  LOWER(slug);
</code></pre><hr><h2 id="performance-considerations"><strong>Performance Considerations</strong></h2><p>Sorting using functions (<code>CAST</code>, <code>SUBSTRING</code>, <code>REGEXP_SUBSTR</code>) makes MySQL unable to use indexes for the <code>ORDER BY</code> step.</p><p><strong>If your table is large</strong>, consider:</p><h3 id="option-a-%E2%80%94-add-a-separate-numeric-column"><strong>Option A — Add a separate numeric column</strong></h3><p>Store the extracted number:</p>

ADD INDEX (slug_num);
</code></pre><p>Now sorting is fully indexed and efficient.</p><hr><h2 id="additional-good-practices"><strong>Additional Good Practices</strong></h2><h3 id="1-enforce-consistent-slug-patterns"><strong>1. Enforce consistent slug patterns</strong></h3><p>Always use <code>smk&lt;number&gt;</code> or <code>r&lt;number&gt;</code><br>Avoid: <code>smk-001</code>, <code>smk_1</code>, <code>SMK1</code>, <code>smk001test</code></p><h3 id="2-zero-padding-is-optional"><strong>2. Zero-padding is optional</strong></h3><p>If you ever use zero-padded slugs (<code>smk001</code>), sorting becomes simpler, but readability suffers.</p><h3 id="3-validate-slug-format-on-insert"><strong>3. Validate slug format on insert</strong></h3><p>Ensure slugs match a predictable pattern:</p><pre><code class="language-regex">^smk[0-9]+$
</code></pre><h3 id="4-consider-storing-structured-data"><strong>4. Consider storing structured data</strong></h3><p>If slugs are meant to be machine-indexable identifiers, keeping numeric and text segments separate improves long-term maintainability.</p><hr><h2 id="finally"><strong>Finally</strong></h2><p>Sorting mixed alphanumeric slugs like <strong><code>smk1</code>, <code>smk20</code>, <code>smk100</code></strong> requires more than a basic <code>ORDER BY</code>.<br>By extracting and converting the numeric segment, you achieve <strong>natural ordering</strong> that aligns with human expectations.</p><p>The most reliable and maintainable solution is:</p><pre><code class="language-sql">SELECT *
FROM `pixie_resources`
WHERE `slug` LIKE 'smk%'
ORDER BY CAST(SUBSTRING(`slug`, 4) AS UNSIGNED);
</code></pre><p>For large tables or complex formats, consider generated columns, numeric indexes, and slug validations.</p><p>Properly handling slug structures not only ensures correct sorting but also improves the long-term scalability and consistency of your data.</p><h3 id="support-us">Support Us</h3>
