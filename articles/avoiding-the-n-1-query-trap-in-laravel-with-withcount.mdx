<p>When working with Laravel Eloquent, one of the most common performance pitfalls is the <strong>N+1 query problem</strong>—and it often happens without developers realizing it.</p><p>Imagine you're displaying a list of blog posts along with the number of comments each one has. You might think this is straightforward:</p><pre><code class="language-php">$posts = Post::all();
foreach ($posts as $post) {
    $post-&gt;comments_count = $post-&gt;comments()-&gt;count(); // 😬
}
</code></pre><p>Looks simple, right? But under the hood, Laravel will:</p><ul><li>Execute <strong>1 query to fetch all posts</strong></li><li>Then <strong>1 query per post</strong> to count comments</li></ul><p>That’s <strong>N+1 queries total</strong>, where N = number of posts. If you have 100 posts, that’s <strong>101 queries</strong>. This quickly gets out of hand and kills performance, especially at scale.</p><hr><h2 id="%E2%9C%85-the-better-way-withcount">✅ The Better Way: <code>withCount()</code></h2><p>Laravel provides a built-in, elegant solution: <code>withCount()</code>. Here’s how you should do it:</p><pre><code class="language-php">$posts = Post::withCount('comments')-&gt;get();
</code></pre><p>This executes <strong>only 1 query</strong>, using SQL’s <code>COUNT()</code> via a <code>LEFT JOIN</code>, and Laravel appends the result as a <code>comments_count</code> attribute to each post.</p><p>Now you can access:</p><pre><code class="language-php">echo $post-&gt;comments_count;
</code></pre><p>No extra queries. No loops. Just fast, clean, efficient code.</p><hr><h2 id="%F0%9F%A7%A0-why-withcount-is-better">🧠 Why <code>withCount()</code> is Better</h2><ul><li><strong>Performance</strong>: Reduces your queries from N+1 to just 1.</li><li><strong>Clean Code</strong>: Avoids manual looping and counting logic.</li><li><strong>Database Optimization</strong>: The database does the counting in one optimized query.</li><li><strong>Scalability</strong>: Works well even with hundreds or thousands of records.</li></ul><hr><h2 id="%F0%9F%9A%80-bonus-multiple-counts-and-aliases">🚀 Bonus: Multiple Counts and Aliases</h2><p>You can count multiple relations in one go:</p><pre><code class="language-php">$posts = Post::withCount(['comments', 'likes']);
</code></pre><p>Or use aliases for clarity:</p><pre><code class="language-php">$posts = Post::withCount([
    'comments as comments_total',
    'likes as total_likes'
]);
</code></pre><p>Now you can access <code>$post-&gt;comments_total</code> and <code>$post-&gt;total_likes</code> with ease.</p><hr><h2 id="%E2%9A%A0%EF%B8%8F-common-mistakes-to-avoid">⚠️ Common Mistakes to Avoid</h2><ul><li><strong>Using <code>count()</code> in a loop</strong> — never do this unless you're intentionally querying live for one record.</li><li><strong>Forgetting to index foreign keys</strong> — if you're using <code>withCount()</code> on large tables, make sure your foreign keys are indexed.</li><li><strong>Assuming <code>with()</code> and <code>withCount()</code> are the same</strong> — <code>with()</code> eager loads the entire relationship, while <code>withCount()</code> only brings in the count.</li></ul><hr><h2 id="finally">Finally</h2><p>When building performant Laravel applications, always be on the lookout for <strong>query inefficiencies</strong>. Small changes like replacing <code>count()</code> in a loop with <code>withCount()</code> can lead to <strong>massive gains</strong> in response time and resource usage.</p><p><strong>Code smart, scale clean.</strong></p><h3 id="support-us">Support Us</h3>
