<p>Working with <strong>Bash</strong> in <strong>Ubuntu</strong> or <strong>WSL (Windows Subsystem for Linux)</strong> is powerful—but not always smooth. If you're a developer or DevOps engineer who jumps between systems, you've probably hit confusing command-line errors more than once.</p><p>This guide breaks down the <strong>most common Bash errors</strong>, explains <strong>why they happen</strong>, and—most importantly—<strong>how to fix them</strong>. Whether you’re writing scripts, running system tools, or just learning the shell, this article will help you get unstuck quickly.</p><hr><h2 id="%E2%9A%A0%EF%B8%8F-1-%E2%80%9Ccommand-not-found%E2%80%9D">⚠️ 1. “Command not found”</h2><p><strong>Error Message:</strong></p><pre><code>foo: command not found
</code></pre><p><strong>Why it happens:</strong></p><ul><li>You mistyped the command name.</li><li>The command isn’t installed.</li><li>The command exists, but the system can’t find it in your <code>$PATH</code>.</li></ul><p><strong>How to fix it:</strong></p><ul><li>Double-check the spelling.</li></ul><p>If it's a custom binary, add the directory to your <code>$PATH</code>:</p><pre><code class="language-bash">export PATH=$PATH:/path/to/your/tool
</code></pre><p>Install it (if available via <code>apt</code>):</p><pre><code class="language-bash">sudo apt update
sudo apt install foo
</code></pre><p>Try locating it:</p><pre><code class="language-bash">which foo
</code></pre><p><strong>Bonus Tip:</strong> Use <code>tab completion</code> to avoid typos.</p><hr><h2 id="%F0%9F%94%90-2-%E2%80%9Cpermission-denied%E2%80%9D">🔐 2. “Permission denied”</h2><p><strong>Error Message:</strong></p><pre><code>bash: ./script.sh: Permission denied
</code></pre><p><strong>Why it happens:</strong></p><ul><li>The script or file is <strong>not executable</strong>.</li><li>You're trying to access a file you don't own or have rights to.</li></ul><p><strong>How to fix it:</strong></p><p>Check file ownership:</p><pre><code class="language-bash">ls -l script.sh
</code></pre><p>Or run it explicitly with Bash:</p><pre><code class="language-bash">bash script.sh
</code></pre><p>Grant execute permission:</p><pre><code class="language-bash">chmod +x script.sh
</code></pre><p><strong>Extra Note:</strong> On WSL, be cautious with file permissions in <code>/mnt/c/...</code>—they might behave differently due to NTFS.</p><hr><h2 id="%F0%9F%93%81-3-%E2%80%9Cno-such-file-or-directory%E2%80%9D">📁 3. “No such file or directory”</h2><p><strong>Error Message:</strong></p><pre><code>bash: ./my_script.sh: No such file or directory
</code></pre><p><strong>Why it happens:</strong></p><ul><li>The file path is wrong or file doesn’t exist.</li><li>You're on the wrong directory.</li><li>The script has <strong>Windows line endings</strong> (<code>\r\n</code>), which makes Linux think it’s not a real file.</li></ul><p><strong>How to fix it:</strong></p><p>Convert Windows line endings to Unix format:</p><pre><code class="language-bash">dos2unix my_script.sh
# or
sed -i 's/\r$//' my_script.sh
</code></pre><p>Verify the file:</p><pre><code class="language-bash">ls -l my_script.sh
</code></pre><p><strong>Pro Tip:</strong> Always configure your text editor (like VS Code) to use <strong>LF</strong> line endings on Linux/WSL.</p><hr><h2 id="%F0%9F%A7%BE-4-%E2%80%9Cbad-interpreter-no-such-file-or-directory%E2%80%9D">🧾 4. “Bad interpreter: No such file or directory”</h2><p><strong>Error Message:</strong></p><pre><code>bash: ./myscript: /bin/bash^M: bad interpreter
</code></pre><p><strong>Why it happens:</strong></p><ul><li>The shebang line (<code>#!/bin/bash</code>) has a hidden <strong>carriage return</strong> character (<code>^M</code>) from Windows.</li></ul><p><strong>How to fix it:</strong></p><p>Or manually clean it:</p><pre><code class="language-bash">sed -i 's/\r$//' myscript
</code></pre><p>Convert the script to Unix format:</p><pre><code class="language-bash">dos2unix myscript
</code></pre><p><strong>Key Insight:</strong> That <code>^M</code> at the end of lines is a sure sign of Windows interference.</p><hr><h2 id="%F0%9F%A7%A8-5-%E2%80%9Csyntax-error-unexpected-end-of-file%E2%80%9D">🧨 5. “Syntax error: unexpected end of file”</h2><p><strong>Why it happens:</strong></p><ul><li>You're missing <code>fi</code>, <code>done</code>, a closing <code>}</code> or quote.</li><li>An <code>if</code>, <code>for</code>, or <code>while</code> block was never properly closed.</li></ul><p><strong>How to fix it:</strong></p><p>Use <code>shellcheck</code> to get line-specific tips:</p><pre><code class="language-bash">sudo apt install shellcheck
shellcheck script.sh
</code></pre><p>Run:</p><pre><code class="language-bash">bash -n script.sh
</code></pre><p>This checks syntax without executing.</p><hr><h2 id="%F0%9F%A7%AA-6-%E2%80%9Cexec-format-error%E2%80%9D-when-running-a-binary">🧪 6. “Exec format error” when running a binary</h2><p><strong>Error Message:</strong></p><pre><code>bash: ./binary: cannot execute binary file: Exec format error
</code></pre><p><strong>Why it happens:</strong></p><ul><li>The file is a <strong>Windows binary</strong>, or compiled for a different architecture (e.g. ARM vs x86).</li></ul><p><strong>How to fix it:</strong></p><ul><li>If it’s Windows-based (<code>PE32</code>), you can’t run it in Bash. Find the Linux version or recompile it.</li></ul><p>Inspect it:</p><pre><code class="language-bash">file binary
</code></pre><hr><h2 id="%F0%9F%A7%A0-7-%E2%80%9Csource-not-found%E2%80%9D">🧠 7. “source: not found”</h2><p><strong>Error Message:</strong></p><pre><code>source: not found
</code></pre><p><strong>Why it happens:</strong></p><ul><li>You're using <code>source</code> in a shell that doesn’t support it (like <code>/bin/sh</code>).</li></ul><p><strong>How to fix it:</strong></p><p>Or explicitly run it with Bash:</p><pre><code class="language-bash">bash -c "source script.sh"
</code></pre><p>Use the POSIX-compliant version:</p><pre><code class="language-bash">. script.sh
</code></pre><hr><h2 id="%F0%9F%A7%B9-8-paths-with-spaces">🧹 8. Paths with Spaces</h2><p><strong>Problem:</strong></p><pre><code class="language-bash">cd /mnt/c/Program Files/
# Results in: No such file or directory
</code></pre><p><strong>Why it happens:</strong></p><ul><li>Bash treats the space as a delimiter unless quoted.</li></ul><p><strong>How to fix it:</strong></p><p>Or escape the space:</p><pre><code class="language-bash">cd /mnt/c/Program\ Files/
</code></pre><p>Quote the path:</p><pre><code class="language-bash">cd "/mnt/c/Program Files/"
</code></pre><hr><h2 id="%F0%9F%AA%9F-9-wsl-specific-scripts-opening-in-notepad">🪟 9. WSL-Specific: Scripts Opening in Notepad</h2><p><strong>Why it happens:</strong></p><ul><li>You try to run a <code>.sh</code> file from <strong>Windows Explorer</strong>, not from the WSL terminal.</li></ul><p><strong>How to fix it:</strong></p><ul><li>Avoid running Bash files by double-clicking in File Explorer.</li></ul><p>Open the Ubuntu/WSL terminal and run:</p><pre><code class="language-bash">./your_script.sh
</code></pre><hr><h2 id="%F0%9F%94%A7-additional-tools-considerations">🔧 Additional Tools &amp; Considerations</h2><h3 id="%E2%9C%85-set-file-executable-by-default">✅ Set File Executable by Default</h3><p>Use this only for a dev environment:</p><pre><code class="language-bash">git config core.fileMode false
</code></pre><h3 id="%F0%9F%94%84-convert-line-endings-before-committing">🔄 Convert Line Endings Before Committing</h3><p>Prevent this problem in Git repos:</p><pre><code class="language-bash"># .gitattributes
*.sh text eol=lf
</code></pre><h3 id="%F0%9F%A7%A0-keep-learning-with-these-tools">🧠 Keep Learning with These Tools:</h3><ul><li><code>shellcheck</code>: Detect common bugs in shell scripts.</li><li><code>set -x</code>: Debug Bash scripts line-by-line.</li><li><code>trap</code> in scripts: Catch and debug errors.</li></ul><hr><h2 id="%E2%9C%85-finally">✅ Finally</h2><p>Bash is powerful—but picky. These errors often come from small missteps: a missing permission, a stray carriage return, or running a command in the wrong shell. But once you understand what Bash is telling you, fixing it becomes second nature.</p><p>If you work in <strong>Ubuntu</strong>, <strong>WSL</strong>, or any Linux-based terminal environment, <strong>mastering these basics will save you hours of frustration</strong>.</p><h3 id="support-us">Support Us</h3>
