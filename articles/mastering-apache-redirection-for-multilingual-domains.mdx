<p>Configuring Apache to handle domain redirection effectively is a critical step in ensuring a seamless user experience, especially when managing multilingual websites. In this article, we’ll explore how to set up redirects for a website where a specific domain should append a language path (e.g., <code>/es</code> for Spanish users). <strong>Understanding and implementing such redirects properly ensures both usability and SEO benefits.</strong></p><h4 id="the-scenario"><strong>The Scenario</strong></h4><p>Suppose you own two domains:</p><ul><li><strong>example.es</strong> (used for Spanish users).</li><li><strong>example.com</strong> (the main website).</li></ul><p>Your goal is to redirect all traffic from <strong>example.es</strong> to <strong>example.com</strong>, with the <strong><code>/es</code> language path</strong> appended. Let’s break down how to achieve this, along with considerations to make your redirection flawless.</p><h4 id="rewrite-rules-explanation"><strong>Rewrite Rules Explanation</strong></h4><p>Here’s an optimized <code>.htaccess</code> file snippet for your use case:</p><pre><code>RewriteEngine On

# Redirect root domain example.es to example.com/es
RewriteCond %{HTTP_HOST} ^(www\.)?example\.es$ [NC]
RewriteRule ^$ https://example.com/es [L,R=301]

# Redirect all other paths from example.es to example.com with /es appended
RewriteCond %{HTTP_HOST} ^(www\.)?example\.es$ [NC]
RewriteRule ^(.*)$ https://example.com/$1/es [L,R=301]
</code></pre><h4 id="key-highlights"><strong>Key Highlights</strong></h4><ol><li><strong><code>RewriteEngine On</code></strong>: Activates mod_rewrite, the Apache module that processes these rules.</li><li><strong><code>RewriteCond %{HTTP_HOST} ^(www\.)?example\.es$ [NC]</code></strong>: Targets requests from <strong>example.es</strong>, regardless of whether "www" is included. The <code>[NC]</code> flag ensures the rule is <strong>case-insensitive</strong>.</li><li><strong>Redirect Root Path</strong>: The first rule ensures that requests for the root domain (e.g., <code>example.es</code>) are redirected to <code>https://example.com/es</code>.</li><li><strong>Redirect Other Paths</strong>: The second rule appends <code>/es</code> to all other paths, preserving the user's original request (e.g., <code>example.es/contact</code> redirects to <code>example.com/contact/es</code>).</li><li><strong><code>R=301</code></strong>: Specifies a <strong>301 redirect</strong>, signaling search engines that this is a permanent change.</li></ol><h4 id="additional-considerations"><strong>Additional Considerations</strong></h4><p>Here are some additional points and enhancements to ensure an even smoother setup:</p><ol><li><strong>Secure HTTPS Redirect</strong><br>Ensure your <strong>example.es</strong> domain forces HTTPS before applying the language redirection. This avoids any mixed content or insecure connection issues.</li></ol><pre><code>RewriteCond %{HTTPS} off
RewriteCond %{HTTP_HOST} ^(www\.)?example\.es$ [NC]
RewriteRule ^ https://%{HTTP_HOST}%{REQUEST_URI} [L,R=301]
</code></pre><ol start="2"><li><strong>Canonical Links for SEO</strong><br>To prevent duplicate content issues between <code>example.com</code> and <code>example.com/es</code>, configure canonical links in your HTML:</li></ol><pre><code class="language-html">&lt;link rel="canonical" href="https://example.com/es"&gt;
</code></pre><ol start="3"><li><strong>Exclude Specific Paths</strong><br>If certain paths on <strong>example.es</strong> shouldn't redirect, add exceptions:</li></ol><pre><code>RewriteCond %{REQUEST_URI} !^/no-redirect-path$
</code></pre><ol start="4"><li><strong>Avoid Redirect Loops</strong><br>If your main domain, <strong>example.com</strong>, already appends <code>/es</code> for Spanish users, check that your rule doesn’t create a loop. For example:</li></ol><pre><code>RewriteCond %{HTTP_HOST} ^(www\.)?example\.es$ [NC]
RewriteCond %{REQUEST_URI} !^/es
RewriteRule ^(.*)$ https://example.com/$1/es [L,R=301]
</code></pre><ol start="5"><li><strong>Testing and Validation</strong></li></ol><ul><ul><li>Use tools like <a href="https://httpstatus.io/" rel="noopener">Redirect Checker</a> to validate the redirects.</li><li>Check Google Search Console for indexing issues after deployment.</li></ul></ul><ol start="6"><li><strong>Page Speed Considerations</strong><br>Avoid multiple redirects in a chain (e.g., <code>http -&gt; https -&gt; /es</code>). Each redirect adds latency. Optimize to reduce the number of hops.</li></ol><h4 id="why-it-matters"><strong>Why It Matters</strong></h4><p>Proper redirection for multilingual sites is <strong>vital for both user experience and SEO</strong>. Users accessing <strong>example.es</strong> expect content tailored for their language, and search engines benefit from clear signals about your content structure. <strong>Without proper redirects</strong>, users could encounter irrelevant content or broken links, reducing trust and engagement.</p><h4 id="finally"><strong>Finally</strong></h4><p>By carefully crafting your <code>.htaccess</code> rules and addressing edge cases, you can ensure a robust redirection setup for your multilingual domains. <strong>Efficient redirects not only enhance usability but also protect your website’s SEO performance</strong>, building a solid foundation for global accessibility.</p><h3 id="support-us">Support Us</h3>
