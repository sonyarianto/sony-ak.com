<p>The <code>deno eval</code> command is a powerful tool that allows developers to quickly run JavaScript or TypeScript code directly from the command line without needing a separate file. It is particularly useful for testing small snippets of code, performing quick calculations, or debugging logic. However, there are nuances to its usage, especially when combined with the <code>-p</code> flag.</p><p>This article explains the behavior of <code>deno eval -p</code> with practical examples, common pitfalls, and additional considerations for using it effectively.</p><h3 id="what-is-deno-eval"><strong>What is <code>deno eval</code>?</strong></h3><p>The <code>deno eval</code> command executes JavaScript or TypeScript code provided as a string argument. This makes it ideal for one-liners or rapid experimentation.</p><p>When paired with the <code>-p</code> flag, the command not only executes the code but also <strong>prints the result of the last evaluated expression</strong> to the console.</p><h3 id="examples-and-behavior"><strong>Examples and Behavior</strong></h3><ol><li><strong>Basic Example</strong></li></ol><pre><code class="language-bash">deno eval -p "1 + 2"
</code></pre><p>Here, the command evaluates the expression <code>1 + 2</code>, and since the <code>-p</code> flag is used, it prints the result to the console.</p><p><strong>Output:</strong></p><pre><code>3</code></pre><p>2. <strong>Using <code>console.log()</code></strong></p><pre><code>deno eval -p "console.log('haha')"
</code></pre><p>This introduces an interesting behavior. The <code>console.log('haha')</code> function outputs <code>"haha"</code> to the console, but it doesn't return anything—it evaluates to <code>undefined</code>. Because the <code>-p</code> flag prints the result of the last evaluated expression, <strong>both the logged output and the <code>undefined</code> are printed.</strong></p><p><strong>Output:</strong></p><pre><code>haha
undefined
</code></pre><p>Here’s what happens:</p><ul><li>The <code>console.log('haha')</code> logs <code>"haha"</code> to the console.</li><li>The <code>undefined</code> comes from the <code>-p</code> flag attempting to print the result of the <code>console.log()</code> function.</li></ul><ol start="3"><li><strong>Returning a Value</strong></li></ol><pre><code class="language-bash">deno eval -p "'hello world'"
</code></pre><p>In this case, the last evaluated expression is a string literal <code>'hello world'</code>. Since this expression evaluates to the string itself, the <code>-p</code> flag prints it directly.</p><p><strong>Output:</strong></p><pre><code>hello world
</code></pre><h3 id="important-points-to-remember"><strong>Important Points to Remember</strong></h3><ol><li><strong>The <code>-p</code> Flag Prints the Last Expression</strong></li></ol><ul><ul><li>The <code>-p</code> flag ensures that the result of the last evaluated expression is printed. If the last expression evaluates to <code>undefined</code>, that's what gets printed.</li></ul></ul><ol start="2"><li><strong>Behavior with Functions Like <code>console.log()</code></strong></li></ol><ul><ul><li>Since <code>console.log()</code> always returns <code>undefined</code>, you’ll see <code>undefined</code> alongside any logged output.</li></ul></ul><ol start="3"><li><strong>Complex Expressions</strong></li></ol><ul><ul><li>You can chain multiple expressions or write more complex code:</li></ul></ul><pre><code>deno eval -p "const x = 5; const y = 10; x * y"
</code></pre><p>Output:</p><pre><code>50</code></pre><ol start="4"><li><strong>TypeScript Support</strong></li></ol><ul><li>You can run TypeScript snippets directly with <code>deno eval</code>. For example:</li></ul><pre><code class="language-bash">deno eval -p "type User = {name: string}; const user: User = {name: 'Alice'}; user.name"
</code></pre><p>Output:</p><pre><code>Alice</code></pre><h3 id="other-considerations"><strong>Other Considerations</strong></h3><ol><li><strong>Escaping Strings</strong></li></ol><ul><li>When passing strings to <code>deno eval</code>, <strong>remember to escape special characters</strong> in the shell. For example:</li></ul><pre><code>deno eval -p "\"Hello, Deno!\""
</code></pre><p>Output:</p><pre><code>Hello, Deno!
</code></pre><ol start="2"><li><strong>Multi-Line Code</strong></li></ol><ul><li>For multi-line code, wrap the entire snippet in double quotes and use semicolons appropriately:</li></ul><pre><code class="language-bash">deno eval -p "const a = 1; const b = 2; a + b"
</code></pre><p>Output:</p><pre><code>3</code></pre><ol start="3"><li><strong>Error Handling</strong></li></ol><ul><li>If your code has an error, Deno will display the error message:</li></ul><pre><code class="language-bash">deno eval -p "const a = 5; a / 0"
</code></pre><p>Output:</p><pre><code>Infinity
</code></pre><h3 id="best-practices"><strong>Best Practices</strong></h3><ol><li><strong>Use <code>-p</code> Only When Necessary</strong><ul><li>Use the <code>-p</code> flag when you explicitly want to print the result of the last expression. If your code relies heavily on <code>console.log()</code> for output, you might not need <code>-p</code>.</li></ul></li><li><strong>Keep Snippets Simple</strong><ul><li>While <code>deno eval</code> supports multi-line code, it’s best to keep your snippets short and simple. For more complex scripts, create a separate <code>.ts</code> file.</li></ul></li><li><strong>Avoid Side Effects</strong><ul><li>Be mindful of any side effects your code might introduce, such as modifying files or network requests.</li></ul></li><li><strong>Readability</strong><ul><li>Write clear and readable code, even for one-liners. Proper spacing and use of variables can make your code easier to debug.</li></ul></li></ol><h3 id="finally"><strong>Finally</strong></h3><p>The <code>deno eval -p</code> command is a handy tool for developers who want to quickly test JavaScript or TypeScript code. By understanding its behavior—especially how the <code>-p</code> flag works—you can use it effectively for a variety of tasks. Remember, <strong>the <code>-p</code> flag always prints the last evaluated expression,</strong> and when using functions like <code>console.log()</code>, you’ll often see <code>undefined</code> as part of the output.</p><p>Mastering these small tools and their quirks can save time and make your development workflow smoother. So go ahead, experiment with <code>deno eval</code>, and see how it can simplify your daily tasks!</p><h3 id="support-us">Support Us</h3>
