<p>When starting a new Laravel project, many developers immediately type:</p><pre><code class="language-bash">composer create-project laravel/laravel myapp
</code></pre><p>That command works perfectly fine, but if you build Laravel applications often, you’ll quickly realize there’s a <strong>faster and more elegant way</strong> to do it. That’s where the <strong>Laravel Installer</strong> comes into play.</p><p>In this article, we’ll explore <strong>what the Laravel Installer is</strong>, <strong>why you should install it globally</strong>, and some <strong>important considerations</strong> that many developers overlook.</p><hr><h2 id="what-is-the-laravel-installer">What is the Laravel Installer?</h2><p>The Laravel Installer is a <strong>command-line utility</strong> created by the Laravel team. Instead of relying solely on Composer to create projects, it gives you the <code>laravel</code> command, making your workflow smoother and faster.</p><p>For example, with the installer, creating a new project becomes as simple as:</p><pre><code class="language-bash">laravel new myapp
</code></pre><p>This feels cleaner and more natural compared to the longer Composer command.</p><hr><h2 id="installing-the-laravel-installer-globally">Installing the Laravel Installer Globally</h2><p>To get started, you run this command:</p><pre><code class="language-bash">composer global require laravel/installer
</code></pre><p>Let’s break it down:</p><ul><li><code><strong>composer</strong></code> → PHP’s package manager (like <code>npm</code> for Node.js).</li><li><strong><code>global</code></strong> → Installs the package in your global Composer directory, not just inside a specific project.</li><li><strong><code>require</code></strong> → Means you’re pulling a new dependency.</li><li><code><strong>laravel/installer</strong></code> → The package that gives you the <code>laravel</code> command.</li></ul><p>After installation, the binary will be placed in your Composer global <code>vendor/bin</code> directory (for example: <code>~/.composer/vendor/bin</code> or <code>~/.config/composer/vendor/bin</code>).</p><hr><h2 id="making-the-laravel-command-available-everywhere">Making the <code>laravel</code> Command Available Everywhere</h2><p>One common frustration after installation is typing <code>laravel</code> and seeing:</p><pre><code>command not found
</code></pre><p>This happens because your system doesn’t yet know where to look for the global Composer binaries. To fix this, you need to <strong>add Composer’s global bin directory to your system PATH</strong>.</p><p>For example:</p><ul><li><strong>Windows:</strong><br>Add <code>%USERPROFILE%\AppData\Roaming\Composer\vendor\bin</code> to your system’s PATH environment variable.</li></ul><p><strong>Linux / macOS (bash/zsh):</strong><br>Add this to <code>~/.bashrc</code> or <code>~/.zshrc</code>:</p><pre><code class="language-bash">export PATH="$HOME/.composer/vendor/bin:$PATH"
</code></pre><p>or (depending on your Composer version):</p><pre><code class="language-bash">export PATH="$HOME/.config/composer/vendor/bin:$PATH"
</code></pre><p>Once done, restart your terminal and you can now run:</p><pre><code class="language-bash">laravel
</code></pre><hr><h2 id="benefits-of-using-the-laravel-installer">Benefits of Using the Laravel Installer</h2><p>Here’s why the Laravel Installer is often preferred:</p><ol><li><strong>Speed</strong> → It uses cached files when available, so creating new projects is much faster.</li><li><strong>Simplicity</strong> → <code>laravel new myapp</code> is shorter and cleaner.</li><li><strong>Consistency</strong> → Always pulls the latest stable release by default.</li><li><strong>Optional presets</strong> → The installer can sometimes provide extra features, like Jetstream or Breeze scaffolding.</li><li><strong>Professional workflow</strong> → If you create multiple projects weekly, this tool saves time and makes your process consistent.</li></ol><hr><h2 id="alternative-without-installer">Alternative Without Installer</h2><p>If you don’t want to install globally, you can still create Laravel projects with:</p><pre><code class="language-bash">composer create-project laravel/laravel myapp
</code></pre><p>This method works everywhere since it relies directly on Composer. However, it’s slower and requires more typing.</p><hr><h2 id="things-to-consider">Things to Consider</h2><p>Before installing globally, keep these in mind:</p><ul><li><strong>Composer version matters</strong> → Make sure you’re running a modern version of Composer (<code>composer --version</code>) to avoid path or permission issues.</li><li><strong>Path conflicts</strong> → On shared servers or environments, global Composer paths may not be set by default. Adjust PATH accordingly.</li></ul><p><strong>Updating the installer</strong> → Over time, you may need to update it:</p><pre><code class="language-bash">composer global update laravel/installer
</code></pre><p><strong>Version pinning</strong> → If you want a specific Laravel version, you can specify it:</p><pre><code class="language-bash">laravel new myapp --dev
</code></pre><p>or</p><pre><code class="language-bash">composer create-project laravel/laravel="10.*" myapp
</code></pre><hr><h2 id="finally">Finally</h2><p>Using <code>composer global require laravel/installer</code> is more than just a convenience. It’s about building a <strong>professional workflow</strong> that saves time, reduces errors, and makes you feel more productive.</p><p>If you’re serious about working with Laravel regularly, the installer should be part of your toolbox. Just remember to configure your PATH correctly and occasionally update the installer to stay aligned with the latest Laravel releases.</p><p>With this in place, the next time you want to spin up a fresh Laravel project, it’s just:</p><pre><code class="language-bash">laravel new projectname
</code></pre><p>Fast, clean, and efficient.</p><h3 id="support-us">Support Us</h3>
