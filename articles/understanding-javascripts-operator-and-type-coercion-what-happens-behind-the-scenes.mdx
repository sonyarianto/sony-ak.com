<p>JavaScript is a powerful language, but its type coercion behavior can sometimes leave us scratching our heads. One of the most common and perplexing operators is the <code>+</code> operator, especially when dealing with non-primitive types like <strong>arrays</strong> and <strong>objects</strong>. In this article, we’ll dive into how JavaScript handles these cases and what happens when you use the <code>+</code> operator with arrays and objects. By the end, you’ll have a clearer understanding of how JavaScript treats different data types and how to avoid some common pitfalls.</p><h3 id="1-the-mystery-of"><strong>1. The Mystery of <code>[] + []</code></strong></h3><p>Let’s start with a basic example:</p><pre><code class="language-javascript">console.log([] + []);
</code></pre><p>At first glance, it might seem like this should do something with arrays, but the result is a bit surprising: <strong>an empty string</strong> (<code>""</code>).</p><h4 id="why-is-this-the-case">Why is this the case?</h4><p>JavaScript, when using the <code>+</code> operator, converts the operands into primitive values (such as strings or numbers) before performing the operation. In this case:</p><ul><li>The first <code>[]</code> (an empty array) is implicitly converted to an empty string (<code>""</code>) because the array’s default string representation is <code>""</code>.</li><li>The second <code>[]</code> is also converted to <code>""</code>.</li></ul><p>When you concatenate two empty strings, you simply get another empty string (<code>""</code>).</p><h3 id="2-the-quirky-object-coercion"><strong>2. <code>[] + {}</code>: The Quirky Object Coercion</strong></h3><p>Next, let’s see what happens when we add an array to an object:</p><pre><code class="language-javascript">console.log([] + {});
</code></pre><p>The output is not what you might expect—<strong><code>[object Object]</code></strong>. But why?</p><h4 id="breakdown">Breakdown:</h4><ul><li>The empty array <code>[]</code> is still converted to an empty string (<code>""</code>).</li><li>The empty object <code>{}</code> is converted to a string as well. In JavaScript, when you convert an object to a string, it calls the object’s <code>toString()</code> method, which for a plain object defaults to <code>[object Object]</code>.</li></ul><p>So, the result of <code>"" + "[object Object]"</code> is <code>[object Object]</code>.</p><h3 id="3-the-curious-case-of-the-block-of-code"><strong>3. <code>{}</code> + []: The Curious Case of the Block of Code</strong></h3><p>Here’s where things get really tricky:</p><pre><code class="language-javascript">console.log({} + []);
</code></pre><p>At first glance, you might think this will behave like the previous examples, but it actually outputs <strong><code>[object Object]</code></strong>. Here's the explanation:</p><ul><li>The <code>{}</code> is <strong>not interpreted as an empty object</strong> because it’s placed immediately before the <code>+</code> operator. In this context, JavaScript treats it as a block of code (like in a function or a loop), not as an object.</li><li>The <code>+</code> operator then tries to add the object (<code>{}</code>) and the array (<code>[]</code>), but since <code>{}</code> is now interpreted as a block of code, the result is the string <code>[object Object]</code>.</li></ul><h4 id="the-fix">The Fix:</h4><p>To get the expected result, you should wrap the object in parentheses like so:</p><pre><code class="language-javascript">console.log(({}) + []);
</code></pre><p>Now, this will output <strong><code>[object Object]</code></strong> because JavaScript interprets it as an object, not a block of code.</p><h3 id="4-important-considerations-type-coercion-at-play"><strong>4. Important Considerations: Type Coercion at Play</strong></h3><p>While we've covered the basics, there are a few other important points to keep in mind when dealing with the <code>+</code> operator and type coercion in JavaScript:</p><ul><li><strong>Arrays and Objects Aren’t Always What They Seem:</strong> When you apply the <code>+</code> operator to non-primitive types, JavaScript converts them to strings or numbers in an unexpected way. This can lead to bugs that are difficult to track down, especially when you're working with complex data structures.</li><li><strong>Implicit Conversion with Numbers:</strong> If any operand involved in a <code>+</code> operation is a number, JavaScript will treat the other operand as a number (if possible). For example:</li></ul><pre><code class="language-javascript">console.log("5" + 5); // "55"
console.log(5 + 5);   // 10
</code></pre><p>In the first case, the string <code>"5"</code> is implicitly converted to a string and concatenated with <code>"5"</code>. In the second, both operands are treated as numbers and added together.</p><ul><li><strong>Object-to-String Conversion:</strong> When an object is involved in a <code>+</code> operation, JavaScript calls the object’s <code>toString()</code> method. If not explicitly defined, objects default to <code>[object Object]</code>. However, you can customize this behavior by defining your own <code>toString()</code> method for objects.</li></ul><pre><code class="language-javascript">const obj = {
  toString: function() {
    return "Custom Object";
  }
};
console.log([] + obj); // "Custom Object"
</code></pre><h3 id="5-how-to-avoid-common-pitfalls"><strong>5. How to Avoid Common Pitfalls</strong></h3><ul><li>Use <code>JSON.stringify()</code> when you want a predictable string representation of an object:</li></ul><pre><code class="language-javascript">const obj = { name: "John" };
console.log([] + JSON.stringify(obj)); // '{"name":"John"}'
</code></pre><ul><li>Always use parentheses when dealing with objects to avoid ambiguity.</li></ul><pre><code class="language-javascript">console.log(({}) + []); // "[object Object]"
</code></pre><ul><li>Be cautious when concatenating arrays, as empty arrays will result in an empty string.</li></ul><pre><code class="language-javascript">console.log([1] + [2]); // "12" (string concatenation, not array merging)
</code></pre><h3 id="finally"><strong>Finally</strong></h3><p>Understanding how JavaScript handles the <code>+</code> operator with arrays and objects can help you avoid unexpected results and bugs. The key takeaway is that <strong>JavaScript relies heavily on type coercion</strong>, and knowing how it converts different data types into primitives can give you more control over your code. By being mindful of these quirks, you can write cleaner, more predictable JavaScript code.</p><h3 id="support-us">Support Us</h3>
