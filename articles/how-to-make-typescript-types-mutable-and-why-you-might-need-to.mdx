<p>In TypeScript, <strong>immutability</strong> is a great feature that protects your data structures from unwanted changes. By using <code>readonly</code> properties, you can ensure that once an object is created, its shape or values can’t be modified accidentally. But sometimes, you do need to mutate the data — especially in scenarios like form editing, cloning objects, or local modifications before pushing changes to a database.</p><p>Let’s talk about how to convert <strong>readonly</strong> properties into <strong>mutable</strong> ones using a clean, reusable pattern in TypeScript.</p><hr><h2 id="%F0%9F%A7%B1-the-problem-readonly-types">🧱 The Problem: Readonly Types</h2><p>Say you have this type:</p><pre><code class="language-ts">type Example = {
  readonly a: string;
  readonly b: number;
};
</code></pre><p>If you try to mutate any of its properties:</p><pre><code class="language-ts">const obj: Example = { a: "hello", b: 42 };
obj.a = "new value"; // ❌ Error!
</code></pre><p>You’ll get an error like:</p><blockquote><em>Cannot assign to 'a' because it is a read-only property.</em></blockquote><p>This is expected behavior — <code>readonly</code> is doing its job. But what if you need to <em>re-use</em> this type in a <strong>mutable context</strong>?</p><hr><h2 id="%E2%9C%85-the-solution-mutablet">✅ The Solution: <code>Mutable&lt;T&gt;</code></h2><p>You can create a utility type that <strong>removes the <code>readonly</code> modifier</strong> from each property:</p><pre><code class="language-ts">type Mutable&lt;T&gt; = {
  -readonly [P in keyof T]: T[P];
};
</code></pre><p>Let’s break that down:</p><ul><li><code>-readonly</code>: removes the <code>readonly</code> modifier</li><li><code>[P in keyof T]</code>: iterates over all properties in type <code>T</code></li><li><code>T[P]</code>: preserves the original type of each property</li></ul><p>Now, using it like this:</p><pre><code class="language-ts">type Result = Mutable&lt;Example&gt;;
</code></pre><p>Results in:</p><pre><code class="language-ts">type Result = {
  a: string;
  b: number;
};
</code></pre><p>Now <code>a</code> and <code>b</code> are both <strong>mutable</strong>! 🎉</p><hr><h2 id="%F0%9F%A7%A0-additional-considerations">🧠 Additional Considerations</h2><p>Here are a few other things you might want to know:</p><h3 id="%F0%9F%94%81-deep-vs-shallow-mutability">🔁 Deep vs Shallow Mutability</h3><p>The <code>Mutable&lt;T&gt;</code> utility above is <strong>shallow</strong> — it only affects the top-level properties. If your type contains nested <code>readonly</code> objects, those will remain readonly.</p><p>For example:</p><pre><code class="language-ts">type Nested = {
  readonly config: {
    readonly version: string;
  };
};
</code></pre><p>Using <code>Mutable&lt;Nested&gt;</code> will give you:</p><pre><code class="language-ts">{
  config: {
    readonly version: string; // still readonly
  };
}
</code></pre><p>If you want <strong>deep mutability</strong>, you can use a recursive version:</p><pre><code class="language-ts">type DeepMutable&lt;T&gt; = {
  -readonly [P in keyof T]: T[P] extends object
    ? DeepMutable&lt;T[P]&gt;
    : T[P];
};
</code></pre><p>Use with caution though — recursive types can get expensive and may lead to performance issues or type complexity in large codebases.</p><hr><h3 id="%E2%9A%A0%EF%B8%8F-when-you-should-not-use-it">⚠️ When You Should NOT Use It</h3><ul><li>When working with data models meant to be immutable (e.g., Redux state, data fetched from APIs).</li><li>When mutability violates domain rules or business logic.</li><li>When you're passing objects between components that expect immutability for safety.</li></ul><p>Mutability is powerful — but like any power, <strong>use it wisely</strong>.</p><hr><h2 id="%F0%9F%92%A1-use-cases-where-this-is-handy">💡 Use Cases Where This is Handy</h2><ul><li>Modifying deeply nested config objects before sending to backend.</li><li>Building forms or UI states based on a <code>readonly</code> schema.</li><li>Testing and mocking with controlled changes.</li><li>Converting third-party types (e.g., from <code>@types</code> packages) into editable forms.</li></ul><hr><h2 id="%F0%9F%A7%AA-bonus-using-as-mutabletype">🧪 Bonus: Using <code>as Mutable&lt;Type&gt;</code></h2><p>Sometimes, you just want a quick escape hatch. You can use TypeScript's type assertion if you're sure of what you're doing:</p><pre><code class="language-ts">(obj as Mutable&lt;Example&gt;).a = "updated";
</code></pre><p>This is <strong>unsafe</strong>, so avoid it unless necessary, and always validate that mutation won't break something downstream.</p><hr><h2 id="%F0%9F%94%9A-finally">🔚 Finally</h2><p>Using <code>Mutable&lt;T&gt;</code> is a <strong>clean</strong>, <strong>reusable</strong>, and <strong>type-safe</strong> way to convert readonly types into mutable ones in TypeScript. It’s a powerful tool in the right contexts — especially when you're dealing with complex data transformations or need flexibility while still keeping type safety.</p><p>Always weigh the <strong>benefits of mutability</strong> against the <strong>risks of unintended side effects</strong>.</p><h3 id="support-us">Support Us</h3>
