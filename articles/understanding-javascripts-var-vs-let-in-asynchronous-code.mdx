<p>When working with <strong>JavaScript</strong>, one of the most common challenges for beginners is understanding how <strong><code>var</code></strong> and <strong><code>let</code></strong> behave in different situations, especially when dealing with <strong>asynchronous code</strong> like the <code>setTimeout</code> function. Let's explore this concept by analyzing two similar code blocks that produce different outputs.</p><p>Imagine you want to loop over a set of numbers and log each value after a slight delay. You might use a <code>for</code> loop with <code>setTimeout</code> like this:</p><pre><code class="language-javascript">for (var i = 0; i &lt; 3; i++) {
  setTimeout(() =&gt; console.log(i), 1);
}
</code></pre><p>At first glance, you might expect this to log <code>0</code>, <code>1</code>, and <code>2</code>. However, when you run the code, it logs <code>3</code> three times. This can be confusing, but the reason lies in how <strong><code>var</code></strong> works in JavaScript.</p><h4 id="why-does-it-log-3">Why Does It Log <code>3</code>?</h4><p>The <strong><code>var</code></strong> keyword is <strong>function-scoped</strong>, meaning it does not create a new binding for each iteration of the loop. Instead, <strong><code>var i</code> refers to the same variable</strong> throughout the loop, and its value is updated at each iteration. By the time the <strong><code>setTimeout</code></strong> callbacks run, the loop has already finished, and <strong><code>i</code> has become <code>3</code></strong>. This is why all three <code>console.log(i)</code> calls print <code>3</code>—because the loop has completed and <strong><code>i</code> remains <code>3</code></strong>.</p><p>Here’s what happens step by step:</p><ol><li>The loop iterates with <code>i = 0</code>, <code>i = 1</code>, and <code>i = 2</code>.</li><li>Each time, <code>setTimeout</code> schedules a function to run later.</li><li>After the loop ends, <code>i</code> is now <code>3</code>.</li><li>When the <code>setTimeout</code> callbacks run, they all refer to this final value of <code>i</code>.</li></ol><p>Now, compare this with a slightly different version of the same loop:</p><pre><code class="language-javascript">for (let i = 0; i &lt; 3; i++) {
  setTimeout(() =&gt; console.log(i), 1);
}
</code></pre><p>This time, the output is exactly what you'd expect: <strong><code>0</code>, <code>1</code>, and <code>2</code></strong>. The reason for this difference is the use of <code><strong>let</strong></code> instead of <code>var</code>.</p><h4 id="why-does-let-work-differently">Why Does <code>let</code> Work Differently?</h4><p>Unlike <code>var</code>, <strong><code>let</code> is block-scoped</strong>, meaning it creates a new binding for <code>i</code> in each iteration of the loop. Each iteration gets its <strong>own copy of <code>i</code></strong>, so when the <code>setTimeout</code> callback is executed, it captures the value of <code>i</code> as it was during that iteration. As a result, the values <code>0</code>, <code>1</code>, and <code>2</code> are printed in sequence, as expected.</p><p>This distinction between <strong>function-scoping</strong> and <strong>block-scoping</strong> is crucial for writing predictable asynchronous JavaScript code. By understanding how <strong><code>let</code></strong> and <strong><code>var</code></strong> behave in loops, you can avoid subtle bugs and ensure that your callbacks reference the correct values.</p><h4 id="important-to-remember">Important to Remember:</h4><ul><li><strong><code>var</code></strong> is <strong>function-scoped</strong>, meaning that all iterations of the loop share the same variable. In asynchronous code, this can lead to unexpected results because the variable might change before the callback runs.</li><li><strong><code>let</code></strong> is <strong>block-scoped</strong>, meaning that each iteration of the loop has its <strong>own instance</strong> of the variable, ensuring that asynchronous callbacks refer to the correct value.</li></ul><p>In summary, when writing loops that involve <strong>asynchronous operations</strong> like <code>setTimeout</code>, it's often better to use <strong><code>let</code></strong> to ensure the behavior you expect. This small change can make a big difference in how your code behaves, especially when dealing with <strong>delayed or asynchronous actions</strong>.</p><h3 id="support-us">Support Us</h3>
