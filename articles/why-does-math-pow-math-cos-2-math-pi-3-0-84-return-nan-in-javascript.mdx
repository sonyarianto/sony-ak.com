<p>When you first start working with JavaScript's math functions, encountering something like <code>NaN</code> (which stands for "Not-a-Number") can be confusing, especially when you think you're working with straightforward numbers. One example of this happens when you try to evaluate something like <code>Math.pow(Math.cos(2 * Math.PI / 3), 0.84)</code>. Instead of getting a nice numeric result, you get <code>NaN</code>. Why?</p><p>Let’s break this down step by step.</p><div class="kg-card kg-callout-card kg-callout-card-blue"><div class="kg-callout-emoji">💡</div><div class="kg-callout-text">Quick demo <a href="https://playcode.io/2052349" rel="noreferrer">here</a> that return NaN.</div></div><h4 id="understanding-the-problem">Understanding the Problem</h4><p>The expression <code>Math.cos(2 * Math.PI / 3)</code> gives us the cosine of an angle. If you're unfamiliar with trigonometry, <strong>cosine</strong> is a function that tells you how far along the x-axis a point on a unit circle is for a given angle.</p><p>When you compute <code>Math.cos(2 * Math.PI / 3)</code>:</p><ul><li>The angle <code>2 * Math.PI / 3</code> corresponds to 120 degrees.</li><li>The cosine of 120 degrees is <strong>-0.5</strong>. So, <code>Math.cos(2 * Math.PI / 3)</code> returns <code>-0.5</code>.</li></ul><p>That’s where things get tricky.</p><h4 id="raising-negative-numbers-to-fractional-powers">Raising Negative Numbers to Fractional Powers</h4><p>Next, you are raising this result (<code>-0.5</code>) to the power of <code>0.84</code> using <code>Math.pow()</code>. The problem here is that raising <strong>negative numbers</strong> to <strong>fractional powers</strong> doesn’t work in the realm of real numbers. Mathematically, doing so results in <strong>complex numbers</strong> (numbers that include imaginary parts, like <code>i</code>).</p><p>However, JavaScript’s <strong>Math.pow() function doesn't handle complex numbers</strong>. It expects to deal only with real numbers. When you try to raise <code>-0.5</code> to <code>0.84</code>, JavaScript can't produce a valid real number result, and it returns <strong>NaN</strong> instead. That’s JavaScript’s way of saying, “I don’t know how to deal with this.”</p><h4 id="the-broader-lesson-on-nan">The Broader Lesson on <code>NaN</code></h4><p>This isn’t just limited to <code>Math.pow()</code> and cosine. Anytime you attempt operations that <strong>don’t have well-defined results in the real number system</strong>, JavaScript will give you <code>NaN</code>. You might run into this with square roots of negative numbers, logarithms of non-positive values, or divisions by zero.</p><p>For example:</p><ul><li><code>Math.sqrt(-1)</code> returns <code>NaN</code> because, again, this is a complex number in math, not something JavaScript’s basic math functions can compute.</li><li><code>Math.log(0)</code> returns <code>-Infinity</code> but attempting <code>Math.log(-1)</code> would return <code>NaN</code>.</li></ul><h4 id="how-to-avoid-nan-in-this-case">How to Avoid <code>NaN</code> in This Case?</h4><p>So, what can you do if you’re running into <code>NaN</code>? Well, one option is to check if the result of <code>Math.cos()</code> is negative before raising it to a fractional power.</p><p>Here’s a simple workaround:</p><pre><code class="language-javascript">let cosValue = Math.cos(2 * Math.PI / 3); // returns -0.5
if (cosValue &lt; 0) {
    // Handle negative case; maybe convert to positive
    cosValue = Math.abs(cosValue);
}
let result = Math.pow(cosValue, 0.84); // Now it works
console.log(result); // Output: a valid number
</code></pre><p>By converting the negative value to its <strong>absolute value</strong>, you avoid the issue. This approach makes sure you’re always working with positive numbers, so you won’t run into the problem of fractional exponents on negative bases.</p><h4 id="should-you-always-use-absolute-values">Should You Always Use Absolute Values?</h4><p>That depends. Using absolute values <strong>changes the meaning of the calculation</strong>. If your specific problem requires working with negative values and you actually need the result of a fractional exponent applied to a negative base, you may need to work in a system that supports <strong>complex numbers</strong>.</p><p>In JavaScript, there are libraries like <strong>math.js</strong> that can handle complex numbers:</p><pre><code class="language-javascript">const math = require('mathjs');

let cosValue = math.cos(2 * math.pi / 3); // -0.5
let result = math.pow(cosValue, 0.84); // Complex number result
console.log(result.toString()); // A complex number output
</code></pre><p>With libraries like these, you can expand beyond real numbers and start dealing with the more advanced math concepts like imaginary and complex numbers.</p><p>The ESM version is below.</p><pre><code class="language-javascript">import { cos, pi, pow } from 'mathjs';

const cosValue = cos(2 * pi / 3); // -0.5
const result = pow(cosValue, 0.84); // Complex number result
console.log(result.toString()); // A complex number output
</code></pre><div class="kg-card kg-callout-card kg-callout-card-blue"><div class="kg-callout-emoji">💡</div><div class="kg-callout-text">Here is the <a href="https://playcode.io/2052342" rel="noreferrer">demo</a> that using mathjs</div></div><h4 id="a-few-more-things-to-keep-in-mind">A Few More Things to Keep in Mind</h4><ol><li><strong>Precision Matters</strong>: When working with trigonometric functions in JavaScript, the values you get are often not perfect. Due to the way floating-point numbers are handled in computers, the result of <code>Math.cos(2 * Math.PI / 3)</code> might be slightly off from <code>-0.5</code>. This usually isn't a big deal, but it’s good to be aware of.</li><li><strong>Handling Edge Cases</strong>: Always think about edge cases where your calculations might return unexpected values like <code>NaN</code> or <code>Infinity</code>. For example, using logarithms on negative numbers, taking square roots of negatives, or dividing by zero. You can guard against these with simple checks like:</li></ol><pre><code class="language-javascript">if (value &lt; 0) {
    // Handle negative values
}
</code></pre><p>or</p><pre><code class="language-javascript">if (isNaN(result)) {
    console.log("Something went wrong in the calculation!");
}
</code></pre><ol start="3"><li><strong>Trigonometry</strong>: If you’re not familiar with trigonometry, the key functions you'll run into are <code>sin</code>, <code>cos</code>, and <code>tan</code>, all of which work on angles. It’s helpful to know that these functions can return <strong>negative values</strong>, depending on the angle.</li></ol><h4 id="finally">Finally</h4><p>The <code>NaN</code> you see when running <code>Math.pow(Math.cos(2 * Math.PI / 3), 0.84)</code> happens because <strong>JavaScript can’t handle raising a negative number to a fractional power</strong> without getting into complex numbers. The simplest solution is to work with the absolute value if you want to avoid <code>NaN</code>. If complex numbers are important to you, you can look into specialized libraries like <code>math.js</code> for more advanced computations.</p><p>Understanding where <strong><code>NaN</code> comes from</strong> and why it appears is important for anyone working with math in JavaScript. It’s not always an error; often, it’s the system’s way of telling you that you’re asking for something it doesn’t know how to compute in the real world of numbers.</p><h3 id="support-us">Support Us</h3>
