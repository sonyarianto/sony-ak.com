<p>Sorting text might look trivial at first glance. You take an array of names, run <code>sort()</code>, and you’re done, right? Well, not exactly. When dealing with <strong>human names, words with accents, or different alphabets</strong>, plain sorting can lead to <strong>unexpected and incorrect results</strong>.</p><p>Let’s explore why <strong>locale-aware sorting</strong> is crucial in PHP and how the <strong>Intl extension’s Collator class</strong> solves this problem.</p><hr><h2 id="the-problem-with-default-sorting">The Problem with Default Sorting</h2><p>Consider the following PHP array:</p><pre><code class="language-php">$names = ['Ása', 'Zoë', 'Émile', 'Ana'];
sort($names);
</code></pre><p>You might expect <code>Ana</code> to come before <code>Ása</code>, but the actual output may surprise you. The default <code>sort()</code> function compares <strong>binary code points</strong>, not linguistic rules.</p><p>That means sorting is based on the <strong>Unicode value</strong> of each character. While this works fine for plain ASCII (A–Z), it fails once <strong>accents, umlauts, and non-English letters</strong> enter the picture.</p><p>For example, <code>Á</code> and <code>É</code> are treated very differently than plain <code>A</code> or <code>E</code>. To a computer, they’re separate characters with their own numeric codes. To a human, though, <code>Ása</code> should clearly be near <code>Ana</code>, not somewhere unexpected.</p><hr><h2 id="enter-collator-%E2%80%93-locale-aware-sorting">Enter <code>Collator</code> – Locale-Aware Sorting</h2><p>The solution is to use the <strong>Intl (Internationalization) extension</strong> in PHP, specifically the <code>Collator</code> class.</p><pre><code class="language-php">$names = ['Ása', 'Zoë', 'Émile', 'Ana'];

$collator = new Collator('fr_FR'); 
usort($names, fn($a, $b) =&gt; $collator-&gt;compare($a, $b));

print_r($names);
</code></pre><p><strong>Result:</strong></p><pre><code>['Ana', 'Ása', 'Émile', 'Zoë']
</code></pre><p>This is <strong>correct French ordering</strong>. Why? Because the <code>Collator</code> understands that in French (<code>fr_FR</code> locale), <code>Ana</code> comes before <code>Ása</code>, and so on.</p><hr><h2 id="why-locale-is-crucial">Why Locale is Crucial</h2><p>Every language has its own rules for alphabetical order. For example:</p><ul><li>In <strong>French</strong>, <code>é</code> is considered close to <code>e</code>.</li><li>In <strong>Swedish</strong>, <code>Å</code>, <code>Ä</code>, and <code>Ö</code> are actually separate letters at the <strong>end</strong> of the alphabet.</li><li>In <strong>German</strong>, <code>ä</code> is usually treated as <code>ae</code>.</li><li>In <strong>Spanish</strong>, <code>ch</code> and <code>ll</code> used to be considered distinct letters (until officially changed in 1994).</li></ul><p>If you’re building software that deals with <strong>international data</strong> (names, cities, dictionaries, product lists), <strong>you cannot rely on default sorting</strong>. You must use a <code>Collator</code> with the correct locale.</p><hr><h2 id="practical-considerations">Practical Considerations</h2><ol><li><strong>Locale Choice</strong><br>Choose the locale carefully:<ul><li><code>fr_FR</code> for French rules</li><li><code>en_US</code> for U.S. English</li><li><code>sv_SE</code> for Swedish</li><li>etc.<br>If your app is multilingual, you might even need <strong>dynamic locale-based sorting</strong> depending on the user’s settings.</li></ul></li><li><strong>Performance Impact</strong><br>Collation is <strong>slower than binary comparison</strong>, especially for large datasets. If you’re sorting millions of rows, consider <strong>database-level collation</strong> (e.g., MySQL <code>utf8mb4_unicode_ci</code>) instead of PHP-only sorting.</li><li><strong>Consistency Between Layers</strong><ul><li>If your database uses one collation (e.g., <code>utf8mb4_general_ci</code>) and PHP uses another (<code>fr_FR</code> Collator), you may see <strong>different results</strong> between backend and frontend. Always keep collation consistent.</li></ul></li><li><strong>Fallback Handling</strong><br>If Intl is not available, provide a safe fallback (like plain <code>sort()</code>) but <strong>warn developers</strong> that results may be incorrect for internationalized data.</li></ol><p><strong>Extension Requirement</strong><br>The <code>Collator</code> class is part of the <strong>Intl extension</strong>. Ensure it’s installed and enabled:</p><pre><code class="language-bash">sudo apt-get install php-intl
</code></pre><p>Without it, your code will break.</p><hr><h2 id="other-use-cases-for-collator">Other Use Cases for Collator</h2><p>Besides sorting, <code>Collator</code> is useful for:</p><ul><li><strong>Case-insensitive comparison</strong> (e.g., “Ana” vs “ana”) without writing hacks.</li><li><strong>Searching</strong> for names or words where diacritics should not block matches.</li><li><strong>Human-friendly comparisons</strong> in multilingual applications.</li></ul><p>Example for comparison:</p><pre><code class="language-php">$collator = new Collator('fr_FR');
echo $collator-&gt;compare('Émile', 'Emile'); // 0 (considered equal in French)
</code></pre><hr><h2 id="finally">Finally</h2><p>When building global applications, <strong>text handling is never trivial</strong>. Sorting strings correctly is not just about “nice to have”—it’s about <strong>respecting cultural rules and providing users with intuitive results</strong>.</p><p>The <strong>Intl Collator</strong> is your best friend for this. It makes sorting <strong>human-aware</strong> instead of <strong>machine-only</strong>.</p><p>So, next time you see an array of names like <code>['Ása', 'Zoë', 'Émile', 'Ana']</code>, remember:</p><ul><li><strong>Default sorting is wrong for humans.</strong></li><li><strong>Collator sorting is right for humans.</strong></li><li>And the locale you choose makes all the difference.</li></ul><hr><p>👉 <strong>Pro tip</strong>: If you’re writing multi-tenant SaaS or global products, always store a user’s locale and apply it everywhere you handle text—sorting, searching, formatting, even pluralization. That’s how you build <strong>truly international-ready software</strong>.</p><h3 id="support-us">Support Us</h3>
