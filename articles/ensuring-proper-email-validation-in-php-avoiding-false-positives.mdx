<p>When working with <strong>email validation in PHP</strong>, you might assume that using <code>FILTER_VALIDATE_EMAIL</code> is enough. However, this built-in filter <strong>can sometimes allow invalid email formats</strong>, leading to unexpected issues in your application. A common example is a string like <code>+44112233</code>, which is clearly not an email, yet PHP may not flag it as invalid.</p><h3 id="why-filtervalidateemail-alone-is-not-enough"><strong>Why <code>FILTER_VALIDATE_EMAIL</code> Alone Is Not Enough</strong></h3><p>PHP's <code>filter_var($email, FILTER_VALIDATE_EMAIL)</code> function <strong>only checks for a valid email syntax</strong> based on the RFC 822 standard. However, this standard is quite broad, allowing many unusual formats that are technically valid but <strong>not suitable for real-world applications</strong>.</p><p>For example:</p><pre><code class="language-php">$email = "+44112233";
if (filter_var($email, FILTER_VALIDATE_EMAIL)) {
    echo "Valid email";
} else {
    echo "Invalid email";
}
</code></pre><p>The above <strong>incorrectly considers</strong> <code>+44112233</code> to be valid because, under RFC rules, it can be interpreted as a valid email with an implicit domain. This is a problem!</p><h3 id="a-more-robust-email-validation-approach"><strong>A More Robust Email Validation Approach</strong></h3><p>To avoid such issues, you should <strong>combine <code>FILTER_VALIDATE_EMAIL</code> with a regular expression</strong> to enforce a stricter format. A better approach is:</p><pre><code class="language-php">$email = "+44112233";

if (!filter_var($email, FILTER_VALIDATE_EMAIL) || !preg_match('/^[^@]+@[^@]+\.[a-zA-Z]{2,}$/', $email)) {
    echo "Invalid email format";
} else {
    echo "Valid email";
}
</code></pre><div class="kg-card kg-callout-card kg-callout-card-blue"><div class="kg-callout-emoji">💡</div><div class="kg-callout-text">Live demo <a href="https://onecompiler.com/php/4397yqkae" rel="noreferrer">here</a>.</div></div><h3 id="breaking-down-the-improved-validation"><strong>Breaking Down the Improved Validation</strong></h3><ol><li><strong><code>FILTER_VALIDATE_EMAIL</code></strong> – Ensures basic email structure is present.</li><li><strong>Regular expression (<code>preg_match</code>)</strong> – Checks if the email contains an <code>@</code> symbol and a valid domain (<code>example.com</code>).<ul><li><code>[^@]+@[^@]+\.[a-zA-Z]{2,}$</code> ensures that:<ul><li>There is at least one character before the <code>@</code>.</li><li>A domain name exists after <code>@</code>.</li><li>The domain contains a dot (<code>.</code>) followed by <strong>at least two letters</strong> (TLD).</li></ul></li></ul></li></ol><h3 id="additional-considerations-for-email-validation"><strong>Additional Considerations for Email Validation</strong></h3><ol><li><strong>Disposable Emails</strong>: Some users use temporary/disposable emails. You can integrate an API or maintain a blacklist to prevent such emails.</li><li><strong>Length Limits</strong>: RFC 5321 states that an email address should be no more than <strong>320 characters long</strong>.</li><li><strong>Allowing Internationalized Domains</strong>: If your application supports <strong>internationalized domain names (IDN)</strong> (e.g., <code>jörg@exämple.de</code>), consider using <code>idn_to_ascii()</code> to normalize the domain before validation.</li></ol><p><strong>DNS Verification</strong>: Checking only the format is not enough; you should verify that the domain exists using <code>checkdnsrr()</code>.</p><pre><code class="language-php">function isValidEmail($email) {
    if (!filter_var($email, FILTER_VALIDATE_EMAIL)) return false;
    $domain = substr(strrchr($email, "@"), 1);
    return checkdnsrr($domain, "MX");
}
</code></pre><p>This ensures that the domain has a valid <strong>Mail Exchange (MX) record</strong>, meaning emails can be received.</p><h3 id="finally"><strong>Finally</strong></h3><p>While PHP provides a built-in function for email validation, it <strong>is not always strict enough</strong> for real-world applications. Combining it with <strong>regular expressions</strong>, <strong>DNS validation</strong>, and <strong>other checks</strong> ensures better accuracy and prevents invalid emails from passing through. By implementing a more robust validation strategy, you can <strong>improve data integrity</strong> and <strong>reduce errors in user input</strong>.</p><h3 id="support-us">Support Us</h3>
