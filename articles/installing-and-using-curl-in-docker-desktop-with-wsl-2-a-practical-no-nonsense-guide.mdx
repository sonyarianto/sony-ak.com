<p>When you first open a <strong>Docker Desktop + WSL 2</strong> Linux shell and type <code>curl</code>, only to be greeted by <em>“command not found”</em>, it feels wrong. After all, <code>curl</code> is one of the most fundamental tools in modern development.</p><p>The confusion usually comes from <strong>not knowing <em>which</em> Linux environment you are actually inside</strong>. Docker Desktop with WSL 2 runs <em>multiple</em> Linux layers, and each one has different rules.</p><p>This article explains <strong>what is really going on</strong>, <strong>where you should install <code>curl</code></strong>, <strong>where you should not</strong>, and <strong>how to structure your setup professionally</strong> so this never becomes a recurring issue.</p><hr><h2 id="understanding-the-three-linux-environments-in-docker-desktop-wsl-2"><strong>Understanding the Three Linux Environments in Docker Desktop + WSL 2</strong></h2><p>Before installing anything, you must clearly distinguish these environments:</p><h3 id="1-your-own-wsl-linux-distribution-ubuntu-debian-alpine-etc"><strong>1. Your own WSL Linux distribution (Ubuntu, Debian, Alpine, etc.)</strong></h3><p>This is what you get when you run:</p><pre><code class="language-powershell">wsl
</code></pre><p>or:</p><pre><code class="language-powershell">wsl -d Ubuntu
</code></pre><p>✔ <strong>You control it</strong><br>✔ <strong>Persistent</strong><br>✔ <strong>Best place for developer tools</strong></p><hr><h3 id="2-docker-desktop-internal-vm"><strong>2. <code>docker-desktop</code> (internal VM)</strong></h3><p>This is Docker Desktop’s internal Linux VM.</p><ul><li>Minimal</li><li>Ephemeral</li><li>Not intended for human interaction</li></ul><p>❌ <strong>Do NOT install tools here</strong><br>❌ <strong>Changes are lost on restart</strong></p><p>You can see it using:</p><pre><code class="language-powershell">wsl -l -v
</code></pre><p>If you see <code>docker-desktop</code>, leave it alone.</p><hr><h3 id="3-linux-inside-containers"><strong>3. Linux inside containers</strong></h3><p>This is the Linux environment <em>inside</em> a running container.</p><p>✔ Controlled by your <strong>Dockerfile</strong><br>✔ Reproducible<br>✔ Correct place for runtime dependencies</p><hr><h2 id="correct-way-to-install-curl-based-on-context"><strong>Correct Way to Install <code>curl</code> (Based on Context)</strong></h2><h3 id="install-curl-in-your-wsl-distro-recommended-for-developers"><strong>Install <code>curl</code> in Your WSL Distro (Recommended for Developers)</strong></h3><p>If you are using <strong>Ubuntu / Debian</strong>:</p><pre><code class="language-bash">sudo apt update
sudo apt install -y curl
</code></pre><p>Verify:</p><pre><code class="language-bash">curl --version
</code></pre><p>This is where tools like <strong>curl, git, node, php, composer, rust, go</strong> belong.</p><hr><h3 id="install-curl-inside-a-container-temporary-or-debugging"><strong>Install <code>curl</code> Inside a Container (Temporary or Debugging)</strong></h3><p>If you entered a container using:</p><pre><code class="language-bash">docker exec -it &lt;container&gt; sh
</code></pre><p>Then install based on the image:</p><h4 id="debian-ubuntu-image">Debian / Ubuntu image</h4><pre><code class="language-bash">apt update &amp;&amp; apt install -y curl
</code></pre><h4 id="alpine-image">Alpine image</h4><pre><code class="language-bash">apk add --no-cache curl
</code></pre><h4 id="rhel-ubi-image">RHEL / UBI image</h4><pre><code class="language-bash">microdnf install curl
</code></pre><p>⚠️ <strong>Important:</strong><br>This installation is <strong>temporary</strong> unless defined in the Dockerfile.</p><hr><h2 id="the-professional-way-install-curl-in-the-dockerfile"><strong>The Professional Way: Install <code>curl</code> in the Dockerfile</strong></h2><p>If your application or debugging process requires <code>curl</code>, <strong>the Dockerfile is the only correct place</strong>.</p><h3 id="debian-ubuntu-example">Debian / Ubuntu example</h3><pre><code class="language-dockerfile">RUN apt-get update \
 &amp;&amp; apt-get install -y curl \
 &amp;&amp; rm -rf /var/lib/apt/lists/*
</code></pre><h3 id="alpine-example">Alpine example</h3><pre><code class="language-dockerfile">RUN apk add --no-cache curl
</code></pre><p><strong>Why this matters:</strong></p><ul><li><strong>Repeatable builds</strong></li><li><strong>CI/CD safe</strong></li><li><strong>No “works on my machine” issues</strong></li><li><strong>Team consistency</strong></li></ul><hr><h2 id="why-docker-desktop-does-not-have-curl-by-design"><strong>Why <code>docker-desktop</code> Does NOT Have <code>curl</code> (By Design)</strong></h2><p>This is not a bug.</p><p>Docker Desktop intentionally:</p><ul><li>Keeps the VM <strong>minimal</strong></li><li>Avoids exposing it as a development environment</li><li>Prevents users from treating it like a normal Linux server</li></ul><p>Any manual installation there:</p><ul><li>Will be lost</li><li>Is unsupported</li><li>Is a dead end</li></ul><p><strong>Docker expects tooling to live either:</strong></p><ul><li>In <strong>containers</strong></li><li>Or in <strong>your own WSL distro</strong></li></ul><hr><h2 id="a-clean-scalable-mental-model"><strong>A Clean, Scalable Mental Model</strong></h2><p>Use this rule of thumb:</p>

<p>If you follow this, your setup will scale from <strong>solo dev</strong> → <strong>team</strong> → <strong>CI/CD</strong> without refactoring.</p><hr><h2 id="additional-points-developers-often-miss"><strong>Additional Points Developers Often Miss</strong></h2><h3 id="1-curl-is-not-always-required-at-runtime"><strong>1. <code>curl</code> is NOT always required at runtime</strong></h3><p>Sometimes <code>curl</code> is only needed for:</p><ul><li>Health checks</li><li>Debugging</li><li>Local testing</li></ul><p>In those cases:</p><ul><li>Use <strong>multi-stage builds</strong></li><li>Keep <code>curl</code> only in the debug stage</li></ul><hr><h3 id="2-prefer-wget-or-native-http-libraries-when-possible"><strong>2. Prefer <code>wget</code> or native HTTP libraries when possible</strong></h3><p>If your app already has:</p><ul><li>Node → <code>fetch</code></li><li>PHP → <code>Guzzle</code></li><li>Go → <code>net/http</code></li><li>Rust → <code>reqwest</code></li></ul><p>Then installing <code>curl</code> inside production containers may be unnecessary.</p><hr><h3 id="3-alpine-images-trade-size-for-convenience"><strong>3. Alpine images trade size for convenience</strong></h3><p>Alpine:</p><ul><li>Smaller images</li><li>Different libc (<code>musl</code>)</li><li>Different tooling</li></ul><p>Sometimes Debian-based images are <strong>better for debugging</strong>, especially when you rely on <code>curl</code>, <code>bash</code>, or CA bundles.</p><hr><h3 id="4-ca-certificates-matter"><strong>4. CA certificates matter</strong></h3><p>If <code>curl</code> fails with TLS errors inside containers, you may need:</p><pre><code class="language-dockerfile">RUN apt-get install -y ca-certificates
</code></pre><p>or (Alpine):</p><pre><code class="language-dockerfile">RUN apk add --no-cache ca-certificates
</code></pre><hr><h2 id="recommended-setup-for-serious-development"><strong>Recommended Setup for Serious Development</strong></h2><p><strong>Best-practice stack:</strong></p><ul><li><strong>Ubuntu WSL</strong> → daily tools</li><li><strong>Docker Desktop</strong> → orchestration only</li><li><strong>Well-defined Dockerfiles</strong> → runtime dependencies</li></ul><p>This setup:</p><ul><li>Avoids confusion</li><li>Keeps environments clean</li><li>Matches how production actually works</li></ul><hr><h2 id="finally"><strong>Finally</strong></h2><p>If <code>curl</code> is missing, the problem is <strong>not the tool</strong> — it’s usually <strong>the mental model</strong>.</p><p>Once you clearly separate:</p><ul><li><strong>Developer environment</strong></li><li><strong>Container runtime</strong></li><li><strong>Docker’s internal VM</strong></li></ul><p>Everything becomes predictable, clean, and maintainable.</p><h3 id="support-us">Support Us</h3>
