<p>Publishing an <strong>NPM package</strong> can sometimes feel like a daunting task, especially if it's been a while since your last release. If you're maintaining a package like <strong>sshmgr</strong> (an imaginary package name), and you've recently updated dependencies or added new features, it's time to publish a <strong>new version</strong>. Here’s a complete guide to ensure a smooth publishing process.</p><hr><h2 id="%F0%9F%93%8C-step-1-update-the-version">📌 Step 1: Update the Version</h2><p>Since you’ve made significant updates (such as upgrading dependencies), follow <strong>semantic versioning (SemVer)</strong> to properly bump your version number.</p><p>For example, if your current version is <code>0.2.4</code> and you've made non-breaking changes and improvements, increase the <strong>minor version</strong>:</p><pre><code class="language-sh">npm version 0.3.0
</code></pre><p>This command will:</p><ul><li><strong>Update</strong> the version in your <code>package.json</code></li><li><strong>Create a Git tag</strong> for <code>v0.3.0</code></li></ul><p>✅ <strong>Tip:</strong> If you’re making small fixes, increase the <strong>patch version</strong> (<code>0.2.4 → 0.2.5</code>). If you introduce breaking changes, bump the <strong>major version</strong> (<code>1.0.0</code>).</p><hr><h2 id="%F0%9F%93%8C-step-2-build-the-package">📌 Step 2: Build the Package</h2><p>Your project is using <strong>TypeScript</strong> and <code>tsup</code> for building. Before publishing, make sure your code is properly compiled:</p><pre><code class="language-sh">npm run build
</code></pre><p>This ensures that the <code>dist/</code> folder contains the latest compiled JavaScript files.</p><p>✅ <strong>Tip:</strong> Double-check that your <code>package.json</code> points to the correct entry file:</p><pre><code class="language-json">"main": "./dist/index.js",
"bin": {
  "sshmgr": "./dist/index.js"
}
</code></pre><p>(Note: <code>sshmgr</code> is an <strong>imaginary package name</strong> for this guide.)</p><hr><h2 id="%F0%9F%93%8C-step-3-login-to-npm">📌 Step 3: Login to NPM</h2><p>If you haven't logged in to NPM recently, you may need to authenticate:</p><pre><code class="language-sh">npm login
</code></pre><p>You’ll be prompted to enter your <strong>NPM username, password, and email</strong>.</p><p>✅ <strong>Tip:</strong> If you're using <strong>2FA (two-factor authentication)</strong>, you'll need to enter an authentication code from your NPM account.</p><hr><h2 id="%F0%9F%93%8C-step-4-verify-before-publishing">📌 Step 4: Verify Before Publishing</h2><p>Before publishing, you can <strong>preview what will be published</strong> by running:</p><pre><code class="language-sh">npm pack
</code></pre><p>This will create a <code>.tgz</code> package file, simulating the publishing process. You can inspect the contents to ensure everything looks correct.</p><p>✅ <strong>Common Mistakes to Check:</strong></p><ul><li>Ensure that the <strong><code>dist/</code></strong> directory exists and contains the built files.</li><li>Confirm that unwanted files (like <code>.git</code>, <code>node_modules</code>, or <code>.env</code>) are <strong>ignored</strong> in <code>.npmignore</code>.</li><li>Run <code>npm list --prod</code> to check installed <strong>dependencies</strong>.</li></ul><hr><h2 id="%F0%9F%93%8C-step-5-publish-the-package">📌 Step 5: Publish the Package</h2><p>Once you're confident everything is correct, publish your package:</p><pre><code class="language-sh">npm publish --access public
</code></pre><p>This will upload your package to the <strong>npm registry</strong>.</p><p>✅ <strong>Important Considerations:</strong></p><ul><li>If your package is <strong>scoped</strong> (e.g., <code>@yourname/sshmgr</code>), you must use <code>--access public</code>.</li><li>If you get a <strong>permission error</strong>, ensure you’re the package <strong>owner</strong> on npm.</li><li>If you get an <strong>already published version error</strong>, update the version with <code>npm version patch</code> or <code>npm version minor</code>.</li></ul><hr><h2 id="%F0%9F%93%8C-step-6-verify-the-published-package">📌 Step 6: Verify the Published Package</h2><p>After publishing, confirm that the new version is available:</p><pre><code class="language-sh">npm view sshmgr version
</code></pre><p>Or check it directly on npm: 🔗 <a href="https://www.npmjs.com/package/sshmgr">https://www.npmjs.com/package/sshmgr</a></p><p>✅ <strong>Tip:</strong> If you find an issue after publishing, you can <strong>deprecate</strong> the version with:</p><pre><code class="language-sh">npm deprecate sshmgr@0.3.0 "This version has a bug, please use 0.3.1"
</code></pre><hr><h2 id="%F0%9F%93%8C-step-7-push-the-changes-to-github">📌 Step 7: Push the Changes to GitHub</h2><p>To keep your repository in sync with the new version, push your changes and tag:</p><pre><code class="language-sh">git add package.json package-lock.json
git commit -m "Bump version to 0.3.0"
git push origin main
git push origin v0.3.0
</code></pre><p>✅ <strong>Tip:</strong> If you use <strong>GitHub Actions</strong> for automated publishing, make sure your workflow is triggered by the new tag.</p><hr><h2 id="%F0%9F%8E%89-finally">🎉 Finally</h2><p>Congratulations! Your updated package is now published and available for everyone to use. 🎉</p><p><strong>Checklist Before Publishing:</strong> ✅ ✔ Version updated (<code>npm version</code>) ✔ Package built (<code>npm run build</code>) ✔ Logged in to npm (<code>npm login</code>) ✔ Verified package contents (<code>npm pack</code>) ✔ Successfully published (<code>npm publish</code>) ✔ Checked the live version (<code>npm view sshmgr version</code>) ✔ Pushed changes to GitHub (<code>git push</code>)</p><p>Now your package <strong>sshmgr@0.3.0</strong> is officially live! 🚀</p><h3 id="support-us">Support Us</h3>
